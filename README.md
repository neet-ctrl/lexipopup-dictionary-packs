# Dictionary Packs Release Repository

This folder is a standalone GitHub repository for generating and publishing the
LexiPopup dictionary database packs as a GitHub Release.

It contains everything required for the `Generate Dictionary Packs` workflow:

```text
dictionary-packs-release/
├── .github/
│   └── workflows/
│       └── generate-dicts.yml
├── scripts/
│   ├── generate_dicts.py
│   └── requirements.txt
├── .gitignore
└── README.md
```

## What the workflow does

When manually started from GitHub Actions, the workflow:

1. Uses Ubuntu and Python 3.11.
2. Installs the Python dependencies.
3. Downloads the required NLTK corpora.
4. Downloads and parses the English Wiktionary JSONL source.
5. Generates:
   - `dict_minimal_v1.db.gz`
   - `dict_standard_v1.db.gz`
   - `dict_full_v1.db.gz`
   - `checksums.txt`
6. Validates that all files and SHA-256 entries exist.
7. Replaces the `dict-v1` GitHub Release.
8. Uploads all four generated files to that release.

The workflow only needs the automatic `GITHUB_TOKEN`. No API key or custom
secret is required.

## Important repository layout

The files in this export must be at the repository root after you push them.
Do not put the `dictionary-packs-release` directory itself inside the new
repository unless you also move its contents to the root. GitHub only detects
workflows under:

```text
.github/workflows/generate-dicts.yml
```

## Move this export into a new repository

From the current project root:

```bash
cd dictionary-packs-release
git init
git branch -M main
git add .
git commit -m "Add standalone dictionary pack release workflow"
git remote add origin https://github.com/neet-ctrl/lexipopup-dictionary-packs.git
git push -u origin main
```

The prepared export is already published at
`neet-ctrl/lexipopup-dictionary-packs`. If you reuse this folder for a
different repository, replace that owner/repository name in the commands and
URLs below.

If the destination repository already has a Git history and you want to place
these files into it, copy the contents of this folder into that repository's
root instead:

```bash
cp -R dictionary-packs-release/. /path/to/your-destination-repo/
cd /path/to/your-destination-repo
git add .
git commit -m "Add dictionary pack release workflow"
git push origin main
```

Do not commit `output/`; it is generated by GitHub Actions and is ignored.

## Run the workflow

1. Open the new GitHub repository.
2. Open **Actions**.
3. Select **Generate Dictionary Packs**.
4. Select **Run workflow**.
5. Select the `main` branch.
6. Click **Run workflow**.

The first full run can take a long time because the Full pack downloads and
parses the large English Wiktionary JSONL source. The workflow timeout is
180 minutes.

## URLs for the Android app

After the workflow completes, the release asset URLs use the new repository:

```text
https://github.com/neet-ctrl/lexipopup-dictionary-packs/releases/download/dict-v1/dict_minimal_v1.db.gz
https://github.com/neet-ctrl/lexipopup-dictionary-packs/releases/download/dict-v1/dict_standard_v1.db.gz
https://github.com/neet-ctrl/lexipopup-dictionary-packs/releases/download/dict-v1/dict_full_v1.db.gz
```

The Android app's `DictionaryDownloadWorker.kt` must use those URLs. The
standalone workflow intentionally does not edit the Android repository because
the Android source is not part of this export.

After each successful workflow run, copy the three SHA-256 values from the
release's `checksums.txt` into the Android app's `PACK_CHECKSUMS` map. This
keeps checksum verification aligned with the new release repository.

## Optional local run

The full generation process needs several gigabytes of temporary disk space
and can take a long time. GitHub Actions is the recommended environment.

If you still want to run it locally from this repository:

```bash
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -r scripts/requirements.txt
python scripts/generate_dicts.py
```

Generated files will appear under `output/`.
